# JWT 验证

JWT (JSON Web Token) 是一种开放标准 (RFC 7519)，用于在各方之间安全地传输信息。它是一种紧凑的、URL安全的方式，以JSON对象形式表示声明，这些声明通常用于身份验证和信息交换。

JWT由三部分组成：
- **头部(Header)** - 指定令牌类型和使用的签名算法
- **负载(Payload)** - 包含声明(claims)，如用户ID、角色、过期时间等
- **签名(Signature)** - 用于验证消息在传输过程中没有被更改

JWT在身份验证流程中的典型使用方式：
1. 用户登录后，服务器生成JWT令牌
2. 令牌返回给客户端并存储（通常在localStorage或cookie中）
3. 后续请求中，客户端在Authorization头部携带此令牌
4. 服务器验证令牌的有效性并授权访问

提供对 JWT Auth 验证的中间件.

## 选择加密提供程序

Salvo 0.95 提供两个可选的 JWT feature：

- `jwt-auth` 使用 AWS-LC provider。
- `jwt-auth-ring` 使用 RustCrypto provider。

正常构建只应启用其中一个。独立的 `ring` feature 用于选择 Salvo rustls
集成的 ring provider，并不会启用 JWT 验证。下面的示例使用 `jwt-auth`；
如果希望改用 RustCrypto，可以这样配置：

```toml
salvo = { version = "0.95", default-features = false, features = ["server", "http1", "ring", "jwt-auth-ring"] }
```

如果 Cargo feature 合并导致两个 JWT provider 同时启用，请在 `main` 的最前面、
任何直接的 `jsonwebtoken` 操作或 JWT 中间件初始化之前调用
`salvo::jwt_auth::install_crypto_provider()`。下面的示例已经这样处理，以确保
provider 的选择是确定的。
