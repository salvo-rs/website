# JWT 驗證

JWT（JSON Web Token）是一種開放標準（RFC 7519），用於在各方之間安全地傳輸資訊。它採用緊湊且URL安全的格式，以JSON物件形式承載聲明內容，通常用於身份驗證與資訊交換。

JWT由三部分組成：
- **標頭（Header）** - 指定權杖類型與使用的簽章演算法
- **載荷（Payload）** - 包含聲明內容，例如使用者ID、角色、過期時間等
- **簽章（Signature）** - 用於驗證訊息在傳輸過程中是否遭竄改

JWT在身份驗證流程中的典型應用方式：
1. 使用者登入後，伺服器產生JWT權杖
2. 權杖傳回客戶端並儲存（通常置於localStorage或cookie中）
3. 後續請求中，客戶端透過Authorization標頭攜帶此權杖
4. 伺服器驗證權杖有效性並授予存取權限

提供JWT身份驗證的中介軟體支援。

## 選擇加密提供者

Salvo 0.95 提供兩個可選的 JWT feature：

- `jwt-auth` 使用 AWS-LC provider。
- `jwt-auth-ring` 使用 RustCrypto provider。

一般建置只應啟用其中一個。獨立的 `ring` feature 用於選擇 Salvo rustls
整合的 ring provider，並不會啟用 JWT 驗證。下方範例使用 `jwt-auth`；
若要改用 RustCrypto，可使用以下設定：

```toml
salvo = { version = "0.95", default-features = false, features = ["server", "http1", "ring", "jwt-auth-ring"] }
```

如果 Cargo feature 合併導致兩個 JWT provider 同時啟用，請在 `main` 的最前面、
任何直接的 `jsonwebtoken` 操作或 JWT 中介軟體初始化之前呼叫
`salvo::jwt_auth::install_crypto_provider()`。下方範例已如此處理，以確保
provider 的選擇是確定的。
